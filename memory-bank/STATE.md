- **ComfyUI는 `engine/ComfyUI`에 SongYUE2 전용으로 독립 설치되어 있음**(포트 8190, `.gitignore` 대상이라 저장소엔 없음 — 다른 PC에서는 `docs/comfyui-setup.md`대로 다시 설치해야 함). `.venv`는 PyTorch 2.14.0+cu130, `comfy-kitchen` 포함(INT8 ConvRot 커널), 총 용량 약 4.1GB. 체크포인트는 `models/checkpoints/`에 하드링크로 연결됨. AudioAuK의 ComfyUI(포트 8189)와는 완전히 별개 프로세스라 서로 영향 없음. `runComfyUi()`가 온디맨드로 `.venv\Scripts\python.exe main.py`를 spawn하므로 사용자가 미리 띄울 필요는 없지만, 최초 1회는 부팅 지연(수십 초)이 있다.
- **audio.cpp `build_windows.ps1`의 `-Models`는 반드시 따옴표로 감쌀 것**: `[string]` 타입 파라미터인데 `-Models yue2,htdemucs,audiosr`처럼 따옴표 없이 쓰면 PowerShell이 쉼표를 배열 연산자로 해석해 `ParameterBindingArgumentTransformationException`이 남 — `-Models "yue2,htdemucs,bs_roformer,audiosr"`로 통째로 문자열로 감싸야 함(2026-09-16 실측, 기존 문서 예시도 이 버그가 있어서 전부 수정함).
- **AudioSR은 출력을 무조건 모노로 만듦**(모델 자체 한계, `--session-option`/`--request-option`에 우회 옵션 없음). SongYUE2의 "음원 복원" 기능은 스테레오 입력을 `ffprobe`로 감지해 `ffmpeg channelsplit`로 L/R 분리 → 채널마다 AudioSR 실행 → `join` 필터로 재결합하는 방식으로 우회함. 이미 무손실인 오디오(YuE2 자체 생성곡 등)에는 AudioSR이 아무 효과가 없다 — 실제로 정보가 소실된 저음질 소스에만 의미 있음.
- **`STEM_MODES`(백엔드)/`STEM_MODE_CONFIG`(프론트)에 모드를 추가하는 패턴은 매우 저비용**: `STEM_NAMES`가 `Object.values(STEM_MODES).flatMap(m => m.stems)`로 자동 유도되므로 `/api/projects/:id/stems/:name` 라우트는 무수정, 프론트 `StemDialog` 컴포넌트도 stem 이름을 하드코딩하지 않아 설정 객체 확장만으로 새 "분리 모드"를 추가할 수 있음("채널 분리"가 AI 모델 없이 이 패턴으로 구현된 선례).
- **MuScriptor(오디오→MIDI)는 audio.cpp에서 `"status": "supported"`로 AudioSR(experimental)과 다름 — 실제로도 매우 안정적/빠름**(RTF≈0.024). `backend/server.mjs`의 `exportMidi()`가 `<곡 파일명>.mid`를 원본 오디오와 같은 폴더에 캐시하므로(mtime 비교), 재다운로드는 즉시 응답한다. 진행률 폴링 UI 없이 단순 `<a href>` 다운로드 링크로 구현되어 있음(음원 복원/ComfyUI처럼 느린 작업엔 이 패턴을 쓰면 안 됨).
- `.abc` 형식 라이브러리 노트는 파일명 기반 id(`abcfile-<base64(파일명)>`)를 쓰므로, 제목을 바꾸면(rename) id도 바뀐다 — JSON 형식 노트(안정적 UUID id)와 다른 특성이니 새 UI를 짤 때 유의할 것.
- `data/settings.json`은 백엔드가 메모리에 캐싱하므로, 프로세스가 떠 있는 동안 파일을 직접 고쳐도 다음 저장 시 덮어써진다 — 반드시 파일 수정 후 프로세스 재시작.
